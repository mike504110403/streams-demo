# 專案規劃 Present - Streams Demo（類抖音直播平台）

**日期**：2026-04-01
**需求摘要**：類抖音直播平台 MVP，支援 Web + Mobile，Vue 3 + Golang

---

## 一、需求規格（PM）

### 核心功能（5 大模組）

| 模組 | 功能重點 |
|------|---------|
| 用戶系統 | 手機號註冊/登入、JWT 認證、個人頁編輯 |
| 直播功能 | 開播推流、觀看拉流、即時觀看人數、結束直播 |
| 直播大廳 | 卡片式列表、下拉刷新、分頁載入、人數排序 |
| 即時彈幕 | WebSocket 文字訊息、彈幕顯示、進入通知 |
| 跨平台 | Chrome/Safari Web + Mobile 裝置支援 |

### User Stories 摘要（共 15 條）
- **P0（必須）**：註冊、登入、開播、觀看、直播列表、發送/接收彈幕
- **P1（重要）**：編輯個人資料、直播標題封面、觀看人數、下拉刷新
- **P2（次要）**：進入直播間系統提示

### Out of Scope
禮物/打賞、直播回放、關注系統、搜尋、美顏濾鏡、連麥、後台管理、推播通知、內容審核、私訊、i18n、付費功能

## 二、技術架構（SA）

### 技術棧

| 層級 | 選擇 | 核心理由 |
|------|------|---------|
| 前端 | **Vue 3 + Vite + Capacitor** | Web 為核心，Capacitor 橋接原生，共用同一份程式碼 |
| UI 庫 | **Vant 4** | 行動端專用、輕量、適合全螢幕客製化 |
| 後端 | **Gin (Go)** | 效能最佳、生態成熟、WebSocket 支援好 |
| 媒體伺服器 | **SRS** | 支援 RTMP/HTTP-FLV/HLS/WebRTC、Docker 一鍵部署 |
| 串流策略 | **RTMP 推流 + HTTP-FLV(Web) + HLS(Mobile)** | 兼顧低延遲與相容性 |
| 彈幕 | **WebSocket (nhooyr.io/websocket)** | Go 最現代的 WebSocket 庫，併發安全 |
| 資料庫 | **PostgreSQL 16 + sqlc** | 型別安全 SQL 生成、零反射 |
| 快取 | **Redis 7** | 線上人數、列表快取、Token 黑名單 |

### 系統架構

```
推流端 ──RTMP──→ SRS ──┬── HTTP-FLV ──→ Web 觀眾（延遲 1-3 秒）
                       ├── HLS ──→ Mobile 觀眾（原生支援）
                       └── HTTP Callback ──→ API Server (Gin)
                                                ├── PostgreSQL
                                                └── Redis
```

### 關鍵決策
1. **MVP 推流限 Web/OBS**，行動端推流延後 Phase 2（大幅降低開發複雜度）
2. **iOS 統一 HLS 拉流**（避開 MSE 相容問題，業界標準做法）
3. **不引入訊息佇列**，Redis Pub/Sub 足夠 MVP 階段

### DB Schema（3 張表）
- `users` — 用戶基本資料
- `streams` — 直播間（含 stream_key、狀態、觀看數）
- `chat_messages` — 彈幕訊息持久化

## 三、Sprint 計畫

| Sprint | 目標 | 主要任務 | 負責代理 |
|--------|------|---------|---------|
| **Sprint 1** | 基礎建設 + 用戶系統 | 專案初始化、DB Schema (users)、註冊/登入 API、前端登入頁 + Token 管理、個人頁 | DBA + BACKEND + FRONTEND |
| **Sprint 2** | 直播核心 | SRS 部署整合、直播間 CRUD API、推流/拉流串接、直播大廳列表 UI | DBA + BACKEND + FRONTEND |
| **Sprint 3** | 即時互動 + 整合 | WebSocket 彈幕服務、彈幕 UI、觀看人數、全流程整合測試、跨裝置適配 | BACKEND + FRONTEND + QA |

### 交付里程碑
- **Sprint 1 完成**：用戶可註冊 → 登入 → 編輯個人資料
- **Sprint 2 完成**：主播可開播 → 觀眾從大廳進入觀看
- **Sprint 3 完成**：完整 MVP — 註冊 → 開播 → 觀看 → 彈幕互動

## 四、風險與建議

| 風險 | 等級 | 建議 |
|------|------|------|
| 行動端推流複雜度高 | 🔴 高 | MVP 先支援 Web/OBS 推流，觀看全平台 |
| iOS HTTP-FLV 不相容 | 🟡 中 | iOS 統一用 HLS，UA 判斷自動切換 |
| SRS 回調可能丟失 | 🟡 中 | 加定時同步任務，每分鐘比對修正 |
| JWT Token 外洩風險 | 🟡 中 | 短效期 + Redis 黑名單 + 登出撤銷 |
| WebSocket 單機瓶頸 | 🟢 低 | MVP 單機足夠，Scale 時加 Redis Pub/Sub |

### PM 補充建議
- SMS 驗證碼 MVP 先用 mock，不串接真實簡訊商
- 檔案儲存（頭像、封面）MVP 用本地儲存，後續遷移 S3/OSS
