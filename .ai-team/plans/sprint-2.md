# Sprint 2 — 直播 UI 優先（前端先行）

**狀態**：待啟動
**目標**：前端完成直播相關所有頁面 UI，使用 Mock 資料，老闆先審核畫面

---

## 策略說明

老闆指示：**前端先行，後端慢一個 Sprint**。
本 Sprint 前端使用 Mock 資料建構完整 UI，後端僅做基礎建設（DB + SRS 環境），不做前後端串接。

---

## 任務分配

### FRONTEND（主力）
- [ ] 直播大廳頁面（卡片式列表、下拉刷新、上拉載入更多）
- [ ] 直播觀看頁面（播放器區域、觀看人數、主播資訊）
- [ ] 開播頁面（攝影機預覽、設定標題/封面、開始直播按鈕）
- [ ] Mock 資料層（假直播列表、假播放畫面）
- [ ] 頁面間路由串接（大廳 → 點擊 → 觀看頁；個人頁 → 開播）

### DBA
- [ ] streams 表 migration
- [ ] 相關索引建立

### BACKEND（基礎建設，不串前端）
- [ ] Docker Compose 加入 SRS 媒體伺服器
- [ ] SRS 基本設定檔（RTMP 收流、HTTP-FLV + HLS 輸出）
- [ ] 直播 API 骨架（路由定義，handler 空殼）

---

## 驗收標準
- 前端：老闆可操作完整 UI 流程（大廳瀏覽 → 進入直播間 → 開播頁面），畫面符合預期
- 後端：SRS 可啟動，能接收 RTMP 推流（用 OBS 手動測試即可）
- **不要求前後端串接**
