## 3. 驗收標準

### 3.1 用戶註冊/登入
| 條件 | Done Definition |
|------|----------------|
| 註冊 | 輸入手機號 → 收到驗證碼 → 輸入驗證碼 → 註冊成功 → 自動登入 |
| 登入 | 輸入手機號 → 收到驗證碼 → 輸入驗證碼 → 登入成功 → 取得 Token |
| Token | Access Token 過期後可用 Refresh Token 自動續期，無感刷新 |
| 登出 | 點擊登出 → Token 失效 → 跳轉登入頁 |
| 異常 | 錯誤的驗證碼 → 顯示錯誤提示；驗證碼 5 分鐘過期 |

### 3.2 開播/觀看
| 條件 | Done Definition |
|------|----------------|
| 開播 | 授權攝影機+麥克風 → 點擊開播 → 推流成功 → 出現在直播列表 |
| 觀看 | 點擊直播卡片 → 進入直播間 → 3 秒內開始播放畫面 |
| 結束 | 主播點擊結束 → 推流中斷 → 觀眾端顯示「直播已結束」 → 從列表移除 |
| 觀看數 | 進入/離開直播間時，觀看人數即時更新（誤差 < 5 秒） |

### 3.3 直播大廳
| 條件 | Done Definition |
|------|----------------|
| 列表 | 顯示封面、標題、主播暱稱、觀看人數 |
| 排序 | 預設按觀看人數降序排列 |
| 分頁 | 每頁 20 筆，滑到底部自動載入下一頁 |
| 刷新 | 下拉刷新後 2 秒內返回最新資料 |
| 空狀態 | 無直播時顯示「目前沒有直播，稍後再來看看」 |

### 3.4 即時聊天
| 條件 | Done Definition |
|------|----------------|
| 發送 | 輸入文字 → 點擊發送 → 訊息即時出現在彈幕區 |
| 接收 | 其他觀眾發送的訊息在 1 秒內顯示 |
| 彈幕 | 訊息以彈幕樣式從右向左飄過畫面，或以列表形式顯示 |
| 系統通知 | 用戶進入直播間時顯示系統訊息 |
| 限制 | 未登入用戶只能觀看，不能發彈幕 |

### 3.5 個人頁
| 條件 | Done Definition |
|------|----------------|
| 顯示 | 頭像、暱稱、簡介正確顯示 |
| 編輯 | 可修改頭像（上傳圖片）、暱稱、簡介 → 儲存成功 → 即時生效 |
| 頭像 | 支援 JPG/PNG，檔案 < 2MB，自動裁切為正方形 |

## 5. Sprint 規劃建議

### Sprint 1 — 基礎建設 + 用戶系統
**目標**：跑通註冊登入流程，建立前後端骨架
- 專案初始化（前端 Vue 3 + 後端 Golang）
- DB Schema：users 表
- API：註冊、登入、Token 刷新、登出
- 前端：登入/註冊頁面、Token 管理
- 基本個人頁（查看 + 編輯）

**交付物**：用戶可完成註冊 → 登入 → 查看/編輯個人資料

### Sprint 2 — 直播核心
**目標**：跑通開播和觀看的完整流程
- 串接流媒體服務（RTMP 推流 / HLS 或 WebRTC 拉流）
- API：建立直播間、結束直播、取得直播資訊
- DB Schema：live_rooms 表
- 前端：開播頁面（攝影機預覽 + 推流）、觀看頁面（播放器）
- 直播大廳列表（含分頁、排序）

**交付物**：主播可開播 → 觀眾從大廳進入直播間觀看

### Sprint 3 — 即時互動 + 整合測試
**目標**：完成彈幕功能，全流程串接
- WebSocket 服務建置
- API：聊天訊息收發、進入/離開通知、觀看人數統計
- DB Schema：chat_messages 表（選擇性持久化）
- 前端：彈幕 UI、訊息輸入框、觀看人數顯示
- 全流程整合測試
- 跨裝置適配調整

**交付物**：完整 MVP — 註冊 → 開播 → 觀看 → 彈幕互動
